## 2. 现有上下文与记忆中心的关系

Codex原有AGENTS、规则、Skill与知识库继续承担行为约束和能力来源；个人背景文件继续承担其原有事实责任。它们没有被整体复制或向量化。对话历史和当前聊天上下文也没有自动搬入中心。正式库中的记忆只通过合格写入产生；隔离测试里的合成记忆不进入正式库。

中心保存适合跨会话复用的最小记忆卡片：用户确认的偏好、项目决策、验证经验和限时交接。当前主模型负责忠实提炼文字；本地Qwen3-Embedding-0.6B把文字编码为向量；SQLite保存正文与修订，Docker Qdrant保存向量。记忆不自动成为规则或权限。

既有个人上下文如需初始化到中心，应另立明确迁入任务：先确定可处理的来源及隐私范围，整理候选、去重、标记时效与来源，经用户核对后选择性导入。全局候选仍须人工批准；原文件保留，不以导入替代本源或删除历史。本次没有批准或实施该迁入任务，不扫描宿主完整会话、认证或其他无关资料。

## 3. 两端连接同一个正式服务

当前共享服务地址为 http://127.0.0.1:8765 ，看板为 http://127.0.0.1:8765/ui 。现有正式数据根是 `<project-root>/runtime/codex`，容器为 `smh-codex-memory`，Qdrant端口6333，集合前缀 `smh_codex_primary`。这些名称来自Codex先完成初始化，**不表示该数据库或容器只供Codex使用**；记忆可见性由服务端身份、范围和工作区绑定决定。

Antigravity应连接此现有中心。不要为了名称对称另建正式数据库、初始化第二套管理员认证、启动第二个8765服务或重命名/迁移现有数据根。测试使用独立实例；正式切换只能把Antigravity客户端接到这个已初始化中心。旧项目根data/config不是当前正式数据根。

服务已为两个客户端准备独立身份。Antigravity客户端程序内部选用 `AGY_CLIENT_TOKEN`，Codex内部选用 `CODEX_CLIENT_TOKEN`；凭据不进入模型上下文、命令文本或日志，不复制进.gemini，不重置现有文件。严禁为普通AI接入使用管理员口令或管理员端点。程序内部加载已授权客户端凭据与让模型查看凭据内容是不同操作。

当前服务端仅登记SharedMemoryHub项目本身。两端在相同实际工作区应使用同一服务端项目绑定，不各造一个同名项目ID。其他项目须由用户通过管理看板明确登记；客户端的工作区提示列表仅帮助发现，不授予访问权限。

## 4. Codex已实施的接入及效果

调用链为：现役AGENTS短触发 → 关联规则索引 `context.shared-memory-hub` → 共用调用规范 → `<explicit-codex-adapter>/cli.py` → 现有服务。

| 改动 | 解决的问题 | 已有证据 |
|---|---|---|
| 主干短触发和唯一索引入口 | 让相关项目任务知道何时、去哪里找记忆 | 非平凡任务真实新会话读取规范并调用search/get |
| 固定codex身份、真实目录和会话来源 | 避免共用CLI默认身份、漏工作区及伪造会话 | 写入回读的actor、project、session一致 |
| 候选最多5条、每条200字摘录，再按ID取正文 | 控制注入上下文的量，保留来源、范围和修订 | 确定性回归与真实工具轨迹 |
| 原键、原请求保存及显式对账 | 写入超时后不重复创建或虚报成功 | 真实服务先提交再丢响应，原键重放后只有1条 |
| 新正式根、手动启停与有界模型预热 | 保留旧数据，并减少首次模型冷加载造成的误报离线 | CUDA实际推理、容器身份、停止端口释放和重启通过 |

服务核心和原共用CLI未在1B改写；Codex主干119行，原管理标记保留。9项确定性适配回归通过；30项1B源码/控制文档指纹本轮核对一致。1A绑定的42项文件仍匹配。源代码未执行Git提交或推送。

结果支持Codex单端受控接入有效，不证明长期稳定性、任何任务必定触发或全量旧记忆已可召回。首次轻量任务未触发检索的记录保留；完整失败与夹具纠错见原验收报告。

## 5. Antigravity薄适配入口的最低要求

由Antigravity先核自身现役主干、发现入口及宿主能力，再按获准范围实施。本文不假定.gemini目录或context.json一定提供可用会话字段，不要求照抄Codex特有变量。

| 对接项 | 必须达到的行为 |
|---|---|
| 触发与发现 | 在自身主干保留最小触发，通过自身现役索引按需读取共用调用规范；普通一次性问答免检 |
| 固定客户端身份 | 程序固定 `client_name="antigravity"`，不能借用Codex适配入口或依赖CLI默认值 |
| 工作区 | 从当前真实宿主工作区取得规范化路径，核服务端绑定；无工作区须显式处理；多根工作区无法确定时暂停相关项目写入 |
| 会话来源 | 核验宿主真实、稳定且可观察的会话ID获取方式；缺失时停止需要该来源的写入，不用时间戳、UUID或旧会话号冒充；读取可独立继续 |
| 凭据与运行状态 | 客户端程序内部加载对应身份；无凭据的本地发现配置可独立，不能改写Codex profile；依赖、缓存、请求记录留在获准所选运行目录区域 |
| 渐进读取 | 普通检索最多5条、每条200字摘录，保留ID、修订、范围、来源及锁定；必要时get正文，不持久缓存检索结果 |
| 写入 | 按既定四类信号，precheck后发送；明确来源、项目、稳定request_key，发送前保护并保存无凭据原请求；规则候选与全局候选待批 |
| 更新与错误 | 保留expected_revision；409锁定/修订冲突不绕过，跨会话提案不称已覆盖；HTTP错误非零退出 |
| 结果未知 | 超时或畸形响应保留原键、原正文和原会话；对账须显式，不换键、不自动重发 |
| 离线与维护 | connect=1.5秒/read=5秒；分别识别网关不可达、维护写冻结及关键词降级；正常调用不启动服务或Docker |

现有 `clients/memory_cli.py` 的 `call_hub` 可复用HTTP传输；**只追加 `--client antigravity` 不等于完成上述适配**。现有CLI不会替宿主决定真实工作区或会话，默认检索可输出完整正文，也没有Codex入口的完整原请求留存和对账封装。Antigravity应补齐这些行为后验收，不新建重复的记忆服务或编排层。

## 6. Antigravity实施顺序、输出和停止条件

1. 只读盘点自己的主干与索引，核工作区和真实会话来源；提交最小接入差异及回退方式。缺会话来源时列为阻塞，不为通过测试伪造。
2. 复用现有服务与接口，完成自己客户端的薄适配；控制资产进入其实际现役home，运行工件落获准所选运行目录，不改Codex控制文件。
3. 在独立合成实例验收身份、绑定、渐进读取、写入来源、全局待批、锁定、TTL、幂等与离线。保存真实新会话轨迹。
4. 按下节完成跨端B1–B3；需要共同操作时使用明确合成记忆与独立实例。不要停止正在日常使用的正式中心来制造离线样本。
5. 用户认可且Antigravity单端门通过后，才把其正式客户端连接到既有中心。保留旧控制基线与数据，不迁入旧个人记忆。更新两端联合回执，准确区分单端、联合及桌面证据。

输出应包含：Antigravity实际差异、适配入口、真实会话ID来源证据、独立测试实例参数、逐项结果、代码与规范哈希、回退说明及未验项。缺凭据加载、来源不明、绑定不明、接口漂移、现役文件并发变化或需要额外安装/迁移时停受影响分支；不扩权解决。本文给出对接设计要求，具体部署动作沿用户届时授权和该端规则执行。

| 编号 | 场景与步骤 | 必须保留的通过证据 | 当前状态 |

| B3 | 明确停止隔离测试网关，分别开启两端真实新会话继续任务 | 一次召回的离线状态、连接阶段及命令总耗时；继续主任务、不猜历史、不自行启动服务或虚报保存 | Codex单端已验证；Antigravity与联合场景未验证 |

原B3“命令1.5秒内完成”的表述修正为连接阶段超时1.5秒、读取阶段5秒，命令总耗时单列。连接拒绝/超时只能证明不可达，模型不能仅凭该错误断言服务已停止。维护期间写冻结不等于所有读取离线。

原B2若只执行浏览器自动化，应单列为受控代理操作；不得替代所声明的用户亲自编辑。Codex原生CLI新会话、Codex桌面App新聊天、Antigravity宿主新会话分别记录，任何一端都不能用伪造身份的HTTP测试替代真实宿主。
