# 换机部署与数据恢复

版本：v0.1.0；日期：2026-11-08；对象：服务v0.3.0、便携维护v0.1.0、Codex接入v0.1.1。当前验证不等于真正换机通过。

## 保存与恢复边界

源码私有仓库负责程序；Codex现役仓库负责调用入口；私密数据包负责正文、版本、提案、项目绑定和永久清除记录。源码与模型不能替代数据备份。备份不包含管理员认证、客户端令牌、会话、Qdrant文件、缓存和虚拟环境。数据包默认未加密；复制到其他电脑须使用用户认可的私密或加密介质。

所有运行输出仍须位于获准的`E:/AI运行区`，拒绝链接路径。当前平台是Windows/Python3.13；换盘、换操作系统需另行适配，不能只改根目录字符串绕过门禁。项目内部入口从源码位置定位，不再依赖旧用户名或唯一项目目录名。

## 首次部署

取得源码后先核对指定提交和`deployment-manifest.json`。安装官方Python3.13、Git及Docker Desktop，驱动和账户由用户单独配置。执行README中的锁定安装命令；仅新增隔离环境，不覆盖旧环境，不刷新锁文件。`portable_setup.py check`检查当前解释器与实际安装版本。模型下载后逐项核对`model.lock.json`，不混用更新的模型修订。

默认新实例先`portable_setup.py prepare`，再双击初始化入口输入新口令。已有认证或数据库不会被普通初始化入口重置。CUDA不可用时显式CPU运行；普通检索仍遵守离线与关键词降级契约。

手动启动在后台线程中预热模型，再开放服务和Worker；冷启动健康等待上限90秒，预热失败如实报告降级。日常客户端仍用既定短超时，不负责启动或冷加载服务。

## 创建一致性数据包

此为用户单独批准的离线维护流程，普通Harness不得自动执行。先通过对应启停器停止服务并确认退出；使用同一实例锁，忙碌即拒绝，不强杀占用进程。

```powershell
& ./.venv-0.3.0/Scripts/python.exe -X utf8 -B scripts/portable_data.py backup --runtime ./runtime/codex --output ./backups/portable-唯一名称 --confirm-offline-maintenance
```

脚本用SQLite一致性备份保存数据，携带完整外部清除记录，核Schema、完整性、指纹、记录数量和清除水位。目标已存在即拒绝。完成后显式恢复原服务，确认健康。旧数据、旧认证与历史备份保留；不把“复制.db文件”当作运行中数据库的一致性备份。

## 在新电脑恢复

把整个数据包复制到本项目`backups/`下，先运行`portable_data.py verify --bundle <数据包目录>`。恢复目标必须不存在；不要恢复进已有正式实例。

```powershell
& ./.venv-0.3.0/Scripts/python.exe -X utf8 -B scripts/portable_data.py restore --bundle ./backups/portable-名称 --target ./runtime/codex --minimum-purge-seq <最新已核水位> --confirm-offline-maintenance
& ./.venv-0.3.0/Scripts/python.exe -X utf8 -B scripts/portable_setup.py prepare --restored-runtime ./runtime/codex
pwsh -NoProfile -File scripts/reset_admin_passcode.ps1 -RuntimeRoot ./runtime/codex
```

恢复历史备份时，还须通过`--latest-tombstone <最新清除记录>`携带制作备份之后的删除，并提供最新已核水位。旧包自身只能证明制作当时的水位，不能知道后来发生的清除；不能只凭旧包保证所有后续删除仍有效。水位不足或记录缺失时拒绝上线。

最后一条只初始化缺失认证，名称为历史兼容；已有认证时拒绝。口令由用户在终端私下输入。恢复包保留旧机来源路径以便追溯；项目工作区绑定须由用户按新机真实路径重新核对，不把整个磁盘绑定为项目。

在确认认证及路径绑定后，通过`portable_setup.py activate-restored`显式启用配置，再手动启动。重建向量任务由串行Worker执行，保留正文修订；没有Qdrant或模型时不能宣称向量恢复成功。

## 核验与回退

至少核对正文ID和修订、提案及历史数量、来源、锁定状态、清除水位、实际召回和停止后的端口释放。永久清除项必须继续不可读，不能因恢复较旧快照而复活。修改过的备份、缺失墓碑、已有目标、活动实例锁、错误路径及未知进程均拒绝。

恢复失败时保留独立目录和回执，旧实例不受影响。回退只切回已核验的旧入口，不删除旧记忆或覆盖后续用户改动。同机隔离恢复只能证明受控试运行；新电脑、桌面新会话和Antigravity联合接入分别验收。
