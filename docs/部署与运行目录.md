# 部署与运行目录

公开协作版 v0.2.0 · 2026-11-11。

## 支持范围

当前锁文件与安装器面向 Windows x64 / Python 3.13。运行目录已与特定盘符、用户名分离；这项源码改进不等于 Linux、macOS 或新电脑安装已经验收。先按 README 运行合成演示，再单独准备真实后端。

## 目录与保护边界

项目根由源码所在位置确定，不依赖当前终端所在目录。默认约定如下：

| 相对位置 | 用途 |
|---|---|
| `.venv-0.3.0/` | 锁定的隔离 Python 环境 |
| `runtime/<instance>/` | 各实例的数据库、认证及实例状态 |
| `models/Qwen3-Embedding-0.6B/` | 锁定模型 |
| `data/qdrant/` | Compose 挂载的向量数据 |
| `cache/` | 由启动器设置的进程缓存和临时文件 |
| `receipts/` | 合成验证输出，不进入 Git |
| `source-snapshots/sessions/` | 可选的授权来源快照；不自动导入 Agent 私人目录 |

写入路径必须位于实际项目根内。符号链接、目录联接和越界写入会被拒绝。应克隆到普通目录，不通过链接目录运行。

只读资产默认也位于项目内。需要复用外部模型或解释器时，可以显式设置单个 `SMH_ASSET_ROOT`；它必须是绝对路径，不能是整个文件系统或盘符根。外部只读根不授予项目外写入权限。

```powershell
# 可选：先自行建立一个只读资产目录，再显式允许它。
$env:SMH_ASSET_ROOT = (Resolve-Path -LiteralPath '..\shared-assets').Path
```

不要为绕过检查而把资产根设成任意父目录。实际模型由 `--model-dir` / `SMH_MODEL_DIR` 指定，配置资产根本身不会下载或加载模型。

## 合成演示

```powershell
& '.\.venv-0.3.0\Scripts\python.exe' -X utf8 -B scripts/demo.py
```

演示将自己的数据放到 `receipts/demo-070/` 下，使用随机端口和新实例，不需要 Docker 或模型。可以通过 `--evidence <项目内目录>` 选择输出位置；`--resume` 仅恢复该演示目录最近记录的合成实例。演示口令、边界和停止方式见 README。

## 真实后端准备

以下是准备清单，不是已通过的新设备部署回执：

1. 用 `scripts/portable_setup.py install` 创建锁定环境；可用 `check` 检查依赖。
2. 确认下载授权与空间后，用 `scripts/download_model.py` 下载模型，并核对 `model.lock.json`。
3. 检查 `docker-compose.yml` 后执行 `docker compose up -d qdrant`。仅 Qdrant 在容器中；HTTP 服务和模型运行在宿主 Python 中。Compose 使用相对挂载和锁定镜像摘要。
4. 为实例选择 `runtime/<instance>/`。`scripts/setup_admin.py --runtime <实例目录>` 从标准输入接收口令，不接收命令行口令。应由自己的交互终端提供，不把口令写入脚本、聊天或历史命令。
5. 用 `scripts/serve_hub.py --runtime <实例目录> --port <端口>` 启动单进程服务，明确 `--device cuda|cpu`、Qdrant 端口、集合前缀及必要的 `--model-dir`。已有认证保留；项目工作区由管理员登记。
6. 先用合成内容分别验证真实向量、权限、离线和停止，再决定是否导入自己的资料。

现有 CPU 参数属于待独立验证路径。不能把演示夹具通过等同于真实 CPU、CUDA 或 Qdrant 通过。服务仅监听回环地址，不应直接公开管理端口。

## 升级与恢复

旧 Schema 通过显式迁移处理，启动不自动改库。升级前停止写入，配套备份数据库、最新清除记录和源码版本；失败时保持停止并核对恢复条件。恢复后重新初始化本机认证、核对项目绑定并重建向量，不从 GitHub 恢复个人记忆。

历史规格中的占位符和旧启停命令仅供沿革参考。当前参数以脚本 `--help`、本指南和[客户端契约](客户端调用规范.md)为准。
