# SharedMemoryHub 客户端调用规范

公开协作版 v0.2.2 · 2026-11-11 · service=0.6.0 / workbench=0.7.0 / schema=600。

本契约面向现有 HTTP 与项目内 CLI。命令示例见 [AI 客户端接入指南](AI客户端接入指南.md)。本版不提供 MCP，不自动安装或启用 Harness 路由。

## 身份、工作区与读取

客户端身份来自认证配置，明确选择 codex 或 antigravity；管理员会话与客户端令牌分离。项目范围由管理员登记的工作区绑定解析，无工作区或未注册目录不能冒充项目写入。来源、主体、读者和宿主限制逐条核对；标签不授权。

- GET `/v1/health`：健康状态。
- POST `/v1/memory/precheck`：写前相关检查。
- POST `/v1/memory/search`：查询候选，传 query、workspace_path、limit 及必要过滤。
- GET `/v1/memory/{memory_id}`：权限允许时读取权威正文。
- POST `/v1/memory/write`：创建、更新、软删除或提交冲突提案。

实际字段为 request_key、operation、memory_id、expected_revision、workspace_path、scope、subject、kind、title、content、confidence，以及 source.origin_type、source.session_id 等来源字段；项目 ID 由可信工作区绑定解析。`/v1/memories/*` 与 idempotency_key 不是当前契约。

确认偏好、项目决定、已验证经验、有期限交接分别保留来源。全局候选、规则候选和跨范围修改仍经人工审批；推断不能自动成为事实。更新保留未提供字段，旧修订和锁定冲突不能覆盖。交接必须保留期限。

调用方先生成固定 request_key 并保留原请求；写超时视为 WRITE_RESULT_UNKNOWN，只能核对或原样重试。通用 memory_cli.py 未实现草稿 CLI 的本地原请求日志，不能假定两者具备同样恢复能力。客户端离线继续主任务，不自行启动中心。

连接等待最多1.5秒、读取等待5秒，与整个命令总耗时不同。当前通用搜索会输出服务正文候选；每条200字摘录的统一渐进投影尚未在所有客户端强制实现。

## 草稿与人工采纳

管理员通过会话、准确 Origin 和 CSRF 使用 `/v1/admin/drafts` 及单条 edit、grant、accept、reject、cancel、restore、purge 操作。写入携带 request_key；除创建外核对 expected_revision。客户端不能取得人工裁决权限。

客户端只可按准确 ID 使用：

- GET `/v1/drafts/{id}`；
- POST `/v1/drafts/{id}/suggestions`；
- GET `/v1/draft-requests/{request_key}`。

单条建议带 request_key、base_draft_revision、base_memory_revision、真实 session_id、kind、fields、reason、questions。ready 为可比较建议，clarify 为澄清问题。原话或授权变化会增版；旧建议保留，不能直接采纳。

Codex 的 draft_cli.py 使用真实 CODEX_THREAD_ID；Antigravity 使用明确 --session-id。缺失时停止写入，不伪造。客户端只能提交建议，用户在看板决定确认状态、锁定编辑和实际边界变化。

草稿不进入普通记忆检索或向量索引。取消不删除原记忆；清除需要当前修订、确认字符串和墓碑对账，202/purge_pending 不等于已完成。

## 关联整理与重复治理

管理员创建草稿可传 members:[{memory_id,base_revision}]，1至50条。所有成员逐条核权，不能借关联草稿扩大访问。

组建议的 changes 逐条覆盖成员，含 memory_id、base_revision、action=keep|update|merge、fields、reason；merge 指定 replacement_id，可带 related_ids。保留目标显式选择 update，完整展示正文和贡献来源。

人工 accept 对每条选择 confirmation=confirmed|hypothesis、proposal_decision=keep|approve|reject，按真实差异确认 confirm_scope_change、confirm_locked_edit。任一成员修订、权限或提案变化均整组拒绝；结果含 before_revision、stored_revision、outcome。undo-apply 产生新修订；后续修改阻止覆盖式撤销。

管理侧 `/v1/admin/memories/related` 最多返回5条候选；文字、主题和显式关联是理由，不证明等义。`/v1/admin/memories/duplicate-review` 对恰好两条当前修订记录 keep_both/defer；同修订不重复提醒，新修订可重新检查。无常驻全库扫描。

完全重复复用已有记录，不覆盖正文或续期。不同主体、项目、条件、权限、期限不能仅凭相似合并。合并后被替代条目暂停并保留来源与历史；不自动永久删除。

确认或复核接口 `/v1/admin/memory/{id}/confirm-review` 不批准适用范围、不启用暂停内容。采纳、组事务、幂等结果及索引任务一并落库；正文提交与索引完成分别报告。

## 版本、恢复与证据

Schema 500→600 显式迁移。备份保留数据库与最新墓碑；清除进度、草稿和关联副本参与恢复对账。启动不自动改旧库，不用旧备份复活已清除内容。

分别记录单端契约、真实客户端、联合调用、浏览器和真实向量后端结果。合成夹具不冒充 CUDA / Docker 或原生双端验收。
